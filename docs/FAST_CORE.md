# EGIN: измерения и границы выполнения

Работа выполнена в существующем Next.js / FastAPI / PostGIS проекте. Python CORE, исходный MapLibre GIS, ML-модель и три контейнера сохранены. Перенос на JavaScript сам по себе не был целью.

## Что показало профилирование

Исходные данные: `artifacts/performance-before.json`, воспроизводимый отчёт `artifacts/performance-before.md`. Chromium, экран 390×844, холодный кэш, обычная сеть и два профиля 4G с CPU ×4. Один прогон каждого сценария; это лабораторные измерения, не полевой INP. SwiftShader отличается от GPU настоящего телефона.

- Главная скачивала 2,48 МБ JS: около 1,83 МБ добавляла интерактивная карта в hero.
- Dashboard возвращал около 98 КБ: дублировались provider raw, погода и подробные анализы.
- JS отдавался без сжатия. На 500 Кбит/с первая WebGL-отрисовка главной занимала около 48,6 с.
- Уже загруженное меню реагировало за 20–55 мс. Переписывание всей бизнес-логики ради UI-задержек не обосновано.

## Реализованные изменения

Главная использует компактный `/bootstrap`, SVG-превью реальных контуров и лениво загружаемые страницы. MapLibre загружается на карте и в профиле поля. JSON и обычные assets сжимаются; SSE исключён из сжатия/буферизации. Bootstrap не ждёт внешние weather/soil/LLM-запросы и не включает полную геометрию, raw provider или секреты.

Client query-store объединяет одинаковые GET, сохраняет данные между переходами, повторяет инвалидированный запрос после завершения уже выполняющегося GET и адресно обновляет подписчиков. Нормализованные поля/хозяйства/диалоги и версионированные события находятся в app-store. Мелкие данные для представления и оптимистичные сообщения обрабатываются на клиенте; сервер подтверждает каждое изменение.

Предварительные площадь, периметр и bbox вычисляются локально без API. PostGIS проверяет исходный контур, геодезическую площадь и revision при сохранении. В микрозамере Node даже 10 000 вершин обрабатывались за 1,46 мс p95 (`artifacts/geometry-preview-profile.json`). Новые Workers/WASM/ONNX не добавлены: измерения не подтвердили пользу. MapLibre продолжает использовать собственные workers. Микрозамер не является гарантией для мобильного CPU.

## События и восстановление

`POST` выполняет изменение; один `GET /events` обслуживает всё приложение. Событие содержит `id`, `type`, `timestamp`, `entityId`, `version`, `payload`. PostgreSQL хранит журнал семь дней; транзакционный advisory lock обеспечивает порядок id по commit, LISTEN/NOTIFY будит подписчиков. Heartbeat — 15 с. Доступ проверяется по актуальному членству, а не по переданному клиентом scope.

Bootstrap и его cursor читаются в одном MVCC snapshot. При обычном reconnect клиент сохраняет последний принятый cursor. Last-Event-ID / after возвращает пропущенные разрешённые события. Истёкший cursor вызывает `resync.required`, новый snapshot и `snapshot.refreshed` для восстановления открытой истории чата. Повторные/старые id отбрасываются. Метки `egin:event:received`, `egin:event:processed` и `egin:event:rendered` отдельно измеряют доставку, синхронную обработку и ближайшие два кадра. Время доставки отсчитывается от timestamp записи в БД и включает commit, очередь и replay, а не только сеть. Это не утверждение о 5 мс и не INP.

## AI и чат

`POST /assistant/messages` создаёт durable job с идемпотентным client_id. Сервер отправляет started/tool/token/completed/error через тот же event bus. Ответ и инструменты сохраняются в PostgreSQL; UI не прекращает генерацию при переходах. Отмена — отдельный POST. История записывается до completed, чтобы её загрузка не опережала commit.

Причины прежних сбоев различаются: Vercel был опубликован без доступного CORE (proxy localhost), а локальная CPU-модель действительно работала, но долго начинала ответ и ошибалась при выборе инструментов/интерпретации истории. Измерения и реальная точность шести запросов отражены в `artifacts/assistant-fast-benchmark.json`; ранние неудачные прогоны сохранены отдельно. Успешный streaming E2E сам по себе не подтверждает точность модели.

В раннем наборе шести перефразированных вопросов jobs завершились: HTTP принятие — 12–17 мс, первый токен — 10,3–49,2 с, полный ответ — 11,7–53,7 с. Затем отдельно проверены шесть точных вопросов пользователя: `artifacts/assistant-requested-questions.json` и подробное сопоставление с инструментами `artifacts/assistant-requested-questions-review.json`. Сохранены до-фикс результаты. Исправлены потеря прогноза в вопросе о дожде, обрезка soil/DEMO-контекста продолжения и пропуск обязательного get_fields для «Какие у меня поля?»; повтор последнего вопроса записывается отдельно.

Качество Qwen 1.7B остаётся ограничением: при правильных исходных данных модель расширяет диапазон дождя на сухой день, даёт неполную рекомендацию культуры или опускает DEMO-квалификацию в прозе. Карточки источников показывают реальные значения и предупреждение об экспериментальном ML. Эта модель не считается проверенным источником агрономических рекомендаций. Live Gemini не проверен без ключа; другой провайдер также потребует фактической проверки. Сравнивать холодное приветствие 29,8 с с шестью разными вопросами как прямое ускорение некорректно.

Чат поддерживает optimistic отправку/retry, стабильный client_id, историю/pagination, reply/edit/delete, пересылку, реакции, read receipts, typing и presence, фотографии/PDF/TXT, карточку поля с ограниченным SVG-контуром, непрочитанный разделитель и сохранение черновиков. Файлы закрыты ACL диалога. Передача поля не предоставляет права редактировать исходное поле. Realtime-проверки выполняются двумя независимыми аккаунтами; результаты — `artifacts/chat-browser-verification.json`.

## Offline и мобильная версия

IndexedDB разделён по пользователю. Сохраняются разрешённые snapshot, поля, прогнозы Open-Meteo, анализы, последние сообщения, черновики и вид карты. Выход очищает локальные данные; 401 очищает сессию, 403/404 удаляют запрещённую запись. Заметки помещаются в очередь с UUID, сервер исключает дубли при повторной доставке. Черновик объявления сохраняет текст; фотографии прикрепляются при публикации.

Service worker кэширует оболочку/статический код, но не API, приватные вложения или массовые картографические тайлы. Кэш Google Weather имеет отдельные ограничения: persist=false, точный expiry, запрет вложенного сохранения и durable weather payload. Приложение показывает отсутствие связи и дату сохранённых источников.

Manifest, иконки и standalone-режим подготовлены для установки. Разрешение уведомлений запрашивается только кнопкой в настройках; разрешённые SSE-уведомления показываются, пока EGIN открыт. Подготовлены service-worker push/notificationclick handlers с переходами только внутри текущего origin. Фоновая Web Push доставка пока не подключена: не заявляется работающий push без серверной конфигурации. IoT и браузерное ML также не изображаются работающими без устройств и подходящей модели.

Загрузка рыночных фото создаёт WebP 1600 px и thumbnail 480 px, удаляет EXIF/GPS/ICC и учитывает ориентацию. Старые JPEG остаются доступны. Проверки мобильных страниц выполняются на 360/375/390/430 px; touch controls имеют размер не менее 44 px в основных сценариях.

## Сервер остаётся источником истины

На сервере остаются secrets, auth/ACL, PostGIS, revisions, поиск рядом, дедупликация, файлы/метаданные, SoilGrids/NASA/Google, ML и LLM. Клиент не может подтвердить права или изменить авторитетные значения. Google доступ отложен по просьбе пользователя; интеграции, ограничения Казахстана и действия для подключения описаны в `GOOGLE_ACCESS.md`. Protocol mocks не выдаются за live-доступ.

Для хозяйств с более чем 200 полями нужен отдельный тест масштаба: bootstrap ограничен 200 summary, полный `/fields` пока возвращает геометрию доступных полей. На текущих данных этот запрос не был узким местом. Административные границы уже загружаются по viewport.

## Повторная проверка

```sh
pnpm typecheck
pnpm lint
node scripts/test-query-cache.mjs
node scripts/test-app-recovery.mjs
node scripts/test-offline-indexeddb.mjs
docker compose exec -T core pytest -q
pnpm --filter @egin/web exec playwright test
PROFILE_LABEL=after PROFILE_SW=block PROFILE_MAP_ROUTES=/map node scripts/profile-browser.mjs
PROFILE_LABEL=after node scripts/profile-report.mjs
PROFILE_LABEL=after-warm-home PROFILE_SW=allow PROFILE_ROUTES=/ PROFILE_MAP_ROUTES=/map PROFILE_CACHE=warm node scripts/profile-browser.mjs
```

LLM и нагрузочные browser-прогоны следует запускать последовательно, чтобы конкуренция за CPU не искажала сравнение. Параллельным Playwright-процессам нужны разные `--output` каталоги. Тесты API создают отдельную одноразовую БД и не меняют данные пользователя.
