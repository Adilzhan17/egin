# EGIN: ход исправлений безопасности

База: `44dee26`. Ветка: `codex/security-hardening-20261107`. Аудит продолжается; этот документ не является итоговым заключением.

## Подготовленные изменения

- Пароли: Argon2id (19 MiB, t=2, p=1), миграция существующего scrypt после успешного входа, ограничение параллельных KDF. Проверка устаревшего результата входа после восстановления доступа.
- Защита входа: резервирование попыток до асинхронной проверки пароля; общий лимит больше не опирается на произвольный X-Real-IP клиента.
- Восстановление: отзыв сессий приложения и developer portal, API-ключей, WebAuthn challenges и QR-входов одного пользователя.
- Sync: allowlist полей записи и данных, отклонение неизвестных полей и попыток записать роль через payload.
- Вложения workspace/developer API: проверка содержимого через декодеры, нормализация формата, ограничение размера; MIME клиента не считается доказательством типа файла.
- HTTP: валидация production origins/RP ID, настройка доверенных proxy, security headers, CSP и HSTS через HTTPS proxy, HTTP redirect на gateway. Исправлено наследование заголовков в Nginx locations с Cache-Control.
- Зависимости: устранены 13 найденных pnpm audit advisory; после изменения lockfile известных advisory в этой проверке нет.
- Сессии: общий проверяющий модуль для HTTP, developer portal, SSE чата и WebSocket SoilCore. Idle timeout приложения — 24 часа, портала — 30 минут; абсолютный срок — 30 дней / 12 часов; не больше 10 сессий каждого вида на пользователя. Повторное подтверждение заменяет cookie, старый перестаёт работать.
- Обязательная MFA через passkey с WebAuthn user verification для platform admin и реальных организаций с ролями owner/admin/trader. Пароль и recovery-сессия не открывают бизнес-операции; сохранены отдельные проверки ролей/tenant. Изолированная симуляция не выдаёт реальных полномочий. MFA-сессия требует нового подтверждения через 12 часов.
- Изменение passkeys/recovery требует подтверждения не старше 10 минут. Если passkey уже настроен, одного пароля недостаточно. Недавний вход по одноразовому recovery-коду разрешает восстановить ключ; это доверенный резервный способ восстановления, а не OTP по email. Выпуск/замена developer API-ключа требует недавнего QR-входа с passkey.
- Добавлен шаг подтверждения личности в настройках безопасности и ссылка из бизнес-ошибки. Flow подтверждения привязан к текущей сессии и используется один раз.
- Асинхронная обработка workspace/developer вложений повторно проверяет сессию/API-ключ перед сохранением.
- Защита deploy, ручного и автоматического rollback: образ без `com.egin.api.auth-security=1` не может обслуживать данные после установки security capability. Проверяется неизменяемый ID образа сохранённого контейнера; ошибка проверки блокирует переключение.
- Логи БД/внешних сервисов: исходные error.message и stack заменены фиксированным событием и allowlist диагностических кодов; текст запроса, DSN, вложенный cause и произвольные поля ошибки не журналируются.
- Git/Docker context: исключены локальные SQLite-файлы, VAPID private key, ключи/контейнеры сертификатов, password-файлы и корневой каталог runtime data.
- Python inference: точные версии прямых и транзитивных зависимостей в requirements.lock; Docker использует этот файл. Запрос ограничен 512 KiB до JSON-разбора, двумя одновременными операциями и 10 секундами на получение тела. Сжатые/не-JSON запросы отклоняются. Схема запрещает лишние поля/нестроковые тексты; OpenAPI/debug отключены.

## Выполненные проверки

### Разделение PostgreSQL (новый этап)

- В production API проверяет подготовленную схему и ограниченные права роли вместо выполнения DDL при запуске. Отдельный мигратор использует bootstrap-учётную запись, сохраняет данные, выдаёт `egin_runtime` только CRUD на рабочие таблицы, чтение служебных версий и доступ к последовательностям. Членство в других ролях, владение таблицами, CREATE, SUPERUSER, CREATEDB, CREATEROLE, REPLICATION и BYPASSRLS блокируют запуск.
- Deploy хранит отдельный runtime-пароль с правами 0600 и не передаёт bootstrap-пароль API. Inference вынесен в другую сеть без доступа к PostgreSQL. Проверка совместимости не позволяет вернуть трафик старому контейнеру с повышенными правами БД.
- Добавлен тест PostgreSQL на сохранение существующих данных, повторный запуск миграций, запрет DDL/изменения служебных версий и запуск всех модулей с ограниченной ролью. Локально он пропущен из-за отсутствия PostgreSQL; ожидается реальный прогон CI.
- 31 тест deployment guards прошёл локально с заглушкой недоступного Windows-модуля fcntl. Это не проверка Docker/Linux на production.
- CI `4637a40`: Market и Mobile прошли. Inventory нашёл только два ожидаемо идемпотентных logout-маршрута; тест уточнён: они обязаны очистить cookie и вернуть только `{ok:true}`. Остальные защищённые маршруты отклонили анонимные обращения.

- `pnpm --filter @egin/api test`: 118 тестов, 102 passed, 16 skipped, 0 failed. Пропуски требуют PostgreSQL, inference, нативных media-инструментов или специального окружения; их нельзя считать пройденными.
- `pnpm build`: TypeScript/Vite приложения и developer portal успешно собраны.
- `pnpm audit --json`: 0 известных advisory в проверенном JavaScript dependency tree; JSON до/после хранится рядом.
- Gitleaks 8.30.1: сканирование доступной Git-истории всех refs и текущих текстовых файлов. Срабатывания изучены; найденные значения — публичные fingerprints/checksums и примеры. Подтверждённых утёкших credentials в проверенном объёме нет. Реальные секреты production и CI недоступны этому аудиту; ротация не выполнялась.
- `python -m py_compile deploy/manage.py`: успешно. Linux-тесты deploy в Windows не запускаются из-за системного модуля fcntl; это не проверка Nginx или production.
- Для второго набора изменений: `pnpm typecheck` успешно; браузерный `security-auth.cjs` с настоящей проверкой WebAuthn и виртуальным Chromium authenticator прошёл (UV отсутствует → отказ; пароль не заменяет существующий passkey; повторный flow/старый cookie отклоняются). Новый сценарий добавлен в Mobile CI.
- 29 unit-тестов границ rollback прошли локально с заглушкой недоступного в Windows модуля fcntl; Docker, Nginx и Linux-блокировка этим запуском не проверялись.
- Полный локальный API-прогон второго набора: 104 passed, 17 skipped, 1 failed — fixture недоступной БД чата передавал db=null. Обработка этого режима исправлена; целевой повторный прогон и CI фиксируют результат отдельно. Новые PostgreSQL MFA-тесты добавлены в Business CI с реальной БД.
- Повторная целевая проверка после исправления db=null: 10 passed, 2 PostgreSQL skipped, 0 failed (chat/developer/security sessions).
- Все четыре GitHub workflow прошли для `1be4463` и `8dbdad4`, включая реальный PostgreSQL, media и новый WebAuthn browser test. Это подтверждение именно этих commit, а не будущих изменений или production.
- Python: pip-audit 2.10.1 проверил 37 разрешённых версий зависимостей, advisory не найдено (`python-audit-before.json`). Resolver запускался в Windows с целевыми wheels Linux/Python 3.12; условные зависимости могут различаться. Поэтому Market CI дополнительно проверяет `pip freeze` реально собранного Linux-образа.
- Inference limits: 4 unit-теста Python прошли. Реальная ONNX-проверка строгой схемы, лимитов и закрытых docs добавлена в Market CI. Локально она пропущена без running inference.
- Логирование: тесты утечки произвольного текста/DSN и существующие news-тесты прошли (4 теста).
- Новый полный перечень защищённых cookie API проверяется без входа на реальном PostgreSQL в Business CI; локальный запуск без PostgreSQL пропускается. Инвентаризация маршрутов уже проверяет точное соответствие реально установленных методов каталогу, но сама по себе не доказывает tenant/role isolation.
