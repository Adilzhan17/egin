# Проверка production владельцем сервера

По решению пользователя настройки действующего сервера проверяет другой контрибьютор с доступом к инфраструктуре. В этой среде нет настроенного SSH-доступа. Проверка публичных адресов вернула HTTP 403 от внешнего слоя и не подтверждает настройки приложения. Этот список — открытая часть ревью, а не подтверждение безопасности production.

Владелец сервера: указать в PR. Окружение, дата и проверенный commit: указать после проверки. Не прикладывать значения секретов, cookies, токенов, DSN или дампы базы.

## Что проверить и приложить к ревью

- [ ] **Остаточные CVE образов:** Trivy после доступных обновлений показывает 49 High в inference и 50 High + 3 Critical в PostgreSQL (срабатывания package/CVE, не подтверждённые атаки). `CVE-2023-45853` для zlib1g классифицирован Debian как неприменимый к этому бинарному пакету; остальные требуют обновления/backport либо подтверждённого разбора достижимости. См. [итоговый отчёт](SECURITY-REPORT-2026-11-07.md) и `container-*-after.json`. Не менять libc/major PostgreSQL на работающем томе без отдельной проверки совместимости и восстановления; не отключать gate и не скрывать все unfixed CVE.

В этой ветке добавлен отдельный PostgreSQL-мигратор (`apps/api/scripts/migrate-database.mjs`) и runtime-роль `egin_runtime`. На staging проверить обновление существующей базы через `manage.py`, сохранение данных, ограничения роли и запуск всех модулей. Не передавать bootstrap-пароль API вручную. После перехода остановить прежние API-контейнеры с bootstrap-учётной записью: они несовместимы с новой границей доступа и не должны оставаться работающими в качестве rollback. Для отката нужен совместимый образ с `com.egin.api.postgres-runtime=1`; deploy дополнительно проверяет реальные права его соединения с БД. Отдельный inference network необходимо проверить на сервере. Эти изменения кода ещё не означают, что конфигурация действующего сервера уже обновлена.

- [ ] **HTTPS и сертификат:** оба домена приложения и портала доступны по HTTPS с действующим сертификатом; HTTP перенаправляет на тот же доверенный домен по HTTPS. Проверить через внешний адрес, включая API, а не только localhost контейнера.
- [ ] **Заголовки:** на HTML, статических файлах, API и ошибках проверить HSTS, CSP, X-Frame-Options, X-Content-Type-Options, Referrer-Policy и Permissions-Policy. Убедиться, что edge не удаляет заголовки. Приложить только заголовки без Set-Cookie и идентификаторов запроса.
- [ ] **Доверие proxy:** API и внутренний Nginx недоступны напрямую из Интернета; внешний proxy перезаписывает переданные клиентом X-Forwarded-For, X-Real-IP и X-Forwarded-Proto. TRUST_PROXY должен перечислять только фактически доверенные сети. Проверить, что подмена этих заголовков не обходит лимит запросов и HTTPS.
- [ ] **База и сеть:** порт PostgreSQL 5432 не опубликован наружу; firewall/security group запрещает внешние подключения. База доступна только нужным сервисам внутренней сети. Приложить перечень открытых портов и назначение сетей без адресов с учётными данными.
- [ ] **Права БД:** рабочая учётная запись приложения — `egin_runtime`, не superuser, не может создавать роли/базы и не имеет BYPASSRLS. Миграции запускаются отдельной учётной записью; bootstrap credentials должны оставаться только у БД и временного мигратора. Проверить реальные credentials работающего API после обновления.
- [ ] **Секреты:** production env находится вне Git, доступен только владельцу/сервису; значения передаются сервером или secret store. Отдельно проверить CI secrets, резервные копии и логи. Подтвердить назначение, владельца и возможность отзыва секретов, не раскрывая значения. Если обнаружится реальная утечка — отозвать/заменить секрет и проверить доступы; удаления строки из Git недостаточно.
- [ ] **Production-настройки:** NODE_ENV=production, точные HTTPS origins и RP ID, отсутствие debug-вывода и публичных внутренних сервисов/метрик. Проверить права на SQLite, ключи шифрования и тома с файлами.
- [ ] **Проверка конфигурации:** запустить тесты deploy в Linux, `nginx -t` для внутреннего Nginx и gateway, проверить запуск образа API с нативным Argon2 и обработку файлов с FFmpeg/qpdf.
- [ ] **Проверка интерфейса:** на staging выполнить вход passkey/паролем, загрузку файлов, чат, карту и 3D; проверить отсутствие неожиданных блокировок CSP и работу cookies через реальную цепочку proxy.
- [ ] **Резервная копия и откат:** подтвердить восстановление backup и совместимость целевого образа с обновлённой схемой/хешами. Deploy сохраняет существующую PostgreSQL до замены образа; ошибка dump либо том без прежнего контейнера останавливают обновление. Проверить эти условия на staging. Старый API не понимает Argon2id; откат на него после миграции паролей недопустим. В PR добавлен guard `com.egin.api.auth-security=1` для deploy/rollback/автовосстановления. Не обходить guard ручным переключением старого контейнера.
- [ ] **MFA и сессии:** администраторы и сотрудники с ролями owner/admin/trader должны иметь passkey с user verification. Проверить регистрацию и резервный ключ до включения ограничений, недавнее подтверждение в настройках, истечение сессии и отдельный QR-вход developer portal. Не публиковать recovery-коды в ревью.

Пункты закрывать только после выполнения с кратким результатом и ссылкой на безопасный лог проверки. До этого в итоговом аудите они остаются непроверенными на production. PR в состоянии draft; изменения не следует сливать или разворачивать до завершения проверки кода и инфраструктуры.
