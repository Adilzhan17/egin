# Огород, советы ИИ и поиск адресов

## Интерфейс

На главной появился блок «Мой огород»: выбор сохранённого участка, влажность почвы на глубине 3–9 см, температура почвы на глубине 6 см и отдельная влажность воздуха. Для нового пользователя — кнопка добавления огорода на карту. Те же показатели доступны в карточке участка.

Кнопка «Как ухаживать сегодня?» запрашивает совет по культуре, погоде, расчётной влажности и последним работам. При переключении участка старый совет очищается. ИИ не вызывается автоматически при открытии главной. Общие рекомендации при недоступности ИИ явно обозначены; отсутствие данных не превращается в нулевую влажность.

Услуги вынесены в основные действия на главной с пояснением «Техника, перевозки и специалисты». Новости расположены сразу после погоды. Поиск в заголовке карты открывает окно для города, района и адреса; выбор результата перемещает Google Maps или MapLibre.

## Источники и ограничения

- [Open-Meteo](https://open-meteo.com/en/docs): почвенные показатели — оценка погодной модели для координат участка. Объёмная доля воды `m³/m³` умножается на 100; это не относительное насыщение почвы и не измерение датчика. Выбирается последний прошедший час, не старше двух часов, по Unix-времени. В UI указаны глубина, время и источник. Кислотность и NPK не вычисляются без анализа почвы.
- [OpenAI Responses / Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs): серверный запрос со строгой JSON-схемой, `store: false`, тайм-аутом и ограничением ответа. По умолчанию `gpt-5-mini-2025-08-07`. В промпте запрещены вымышленные измерения, универсальные нормы полива по одному проценту и назначения препаратов. Ответ справочный, требует проверки состояния грядки.
- [Nominatim policy](https://operations.osmfoundation.org/policies/nominatim/): только явные запросы, Казахстан, максимум пять результатов, идентификация приложения и видимая атрибуция OpenStreetMap. Сервер ограничивает исходящие запросы одним за 1,1 секунды и кэширует результаты на сутки. Публичный сервис рассчитан здесь на **один экземпляр backend**; перед масштабированием нужен общий ограничитель или собственный/коммерческий Nominatim-совместимый провайдер. Провайдер переключается через окружение.

## API и конфигурация

- `GET /farm-plots/:plotId/conditions` — JWT, доступ только владельцу или администратору; возвращает `status` и `conditions`, без обращения к ИИ.
- `GET /farm-plots/:plotId/ai-advice?language=ru|kk` — те же права, до пяти запросов в минуту на клиента. Успешные советы кэшируются до десяти минут с учётом участка, журнала, погоды и языка; одновременные одинаковые запросы объединяются.
- `GET /places/search?q=...&language=ru|kk` — JWT, 3–200 символов, до двадцати запросов в минуту на клиента плюс общий лимит провайдера. Пустой результат и недоступность сервиса различаются.

Серверные переменные:

```dotenv
OPENAI_API_KEY=<server secret>
OPENAI_MODEL=gpt-5-mini-2025-08-07
GEOCODING_SEARCH_URL=https://nominatim.openstreetmap.org/search
```

Ключ нельзя помещать в `NEXT_PUBLIC_*`, исходники, образы или Git. Локальный `backend/.env` исключён из Git. `docker-compose.selfhost.yml` передаёт переменные из серверного `.env`; `docker-compose.prod.yml` уже использует `env_file`. После настройки нужно пересоздать backend, а frontend обновить вместе с API. Локальный `.env` не настраивает окружение рабочего сервера. Ключ, ранее отправленный в переписке, следует заменить при настройке серверного секрета.

Для SSH-деплоя через GitHub Actions создайте отдельный repository secret `OPENAI_API_KEY`: значение — только ключ. После успешных проверок push в `main` обновляет backend через `scripts/deploy-backend.sh`, который сохраняет серверные настройки и заменяет только ключ, если он передан. `PROD_ENV_FILE` редактировать не нужно. Порт SSH задаётся repository variable `SSH_PORT` (по умолчанию `22`). Frontend публикуется отдельно в Cloudflare Workers. Подробности и восстановление при ошибке — в [TESTING.md](TESTING.md#backend-deployment-over-ssh).

## Проверка 25 сентября 2026

- Модульные тесты: единицы измерения, выбор времени, пропуски/некорректные данные, кэш и объединение запросов; права на чужой участок; ответы и отказы ИИ; поиск, кэш и лимиты; единицы ветра для агро-предупреждений.
- Production-сборка frontend, TypeScript и ESLint изменённых компонентов.
- Chrome, эмуляция 320, 390, 1440 px: нет горизонтального переполнения, новости после погоды, совет только по кнопке, смена участка очищает совет, поиск только после отправки формы, выбор адреса закрывает окно. API в браузерном сценарии подменены тестовыми данными; реальные устройства и перемещение живой карты не проверялись.
- Отдельные живые запросы: Open-Meteo вернул почвенные показатели; OpenAI вернул структурированный совет для синтетического огорода; Nominatim нашёл адрес в Алматы.
- Полная локальная сборка backend и проверка всех HTTP-маршрутов заблокированы отсутствующим в локальном `node_modules` пакетом `@nestjs/throttler`, уже указанным в зависимостях проекта. Пакеты не скачивались согласно `.agents/rules/1.md`. CI устанавливает зависимости и должен выполнить полную сборку и route contract.
- Изменения не развёрнуты на рабочем сервере в рамках этой проверки.
