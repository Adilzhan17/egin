# Культуры и создание участка

Локальная реализация в существующем EGIN. Публикация и push не выполнялись.

## Как проверить руками

1. Открыть `http://localhost:4935/#/fields` и войти в свой профиль для серверного сохранения.
2. Нажать «Добавить участок». Нарисовать контур, выбрать его через существующий ЕГКН-поиск или загрузить GeoJSON WGS84.
3. Выбрать одну из четырёх культур. Указать название; стадию и дату можно оставить неизвестными.
4. Проверить карту, рассчитанную площадь и 3D-предпросмотр. Нажать «Сохранить участок».
5. После подтверждения сервером откроется карточка созданного участка. «Открыть цифровой двойник» ведёт на главную.
6. Создать второй участок и переключать их селектором над сценой. После перезагрузки выбранный участок сохраняется.
7. В «Настройках участка» изменить культуру и повторно сохранить. На главной отобразится новая культура этого участка.

При ошибке отправки мастер остаётся открытым, показывает ошибку и позволяет повторить попытку. Черновик сохраняется в браузере, включая шаг, геометрию и параметры. Для гостя серверный успех не показывается; после входа доступно явное восстановление гостевого черновика с этого устройства. IoT-станция для создания участка не нужна.

Для каждой культуры есть три детерминированных варианта, четыре состояния геометрии, два уровня детализации. Материалы объединены, повторяющиеся растения рисуются через instancing. Карточки используют PNG, полученные рендером этих же моделей. Это ботанические иллюстрации, не сканы конкретных сортов. Ряды и число растений не означают измеренную плотность посадки или урожайность.

Исходные снимки `before-*.png` сняты до обновления сборки; `after-*.png` сняты в отдельной сцене при дневном освещении. Различия освещения, кадрирования и стадии прямо отмечены в сравнении. `home-after-*.png` показывают интеграцию в приложение с реально сохранёнными тестовыми участками.

## Мастер

Путь: границы → культура → выращивание → проверка → подтверждённое сохранение.

- Карта позволяет ставить и перетаскивать вершины, вставлять вершины на ребре, отменять последнюю точку и начать заново.
- Площадь и внутренняя точка рассчитываются существующим `measureBoundary`. Самопересечения, незамкнутые/вырожденные контуры и неверные координаты отклоняются. Импорт сохраняет внутренние вырезы.
- Выбор готового контура использует существующий ЕГКН-процесс. Он возвращает геометрию в мастер, без преждевременного создания записи.
- Название и культура обязательны. Дата не используется для выдуманного определения стадии.
- Неизвестная стадия подписана явно; для неё показано зрелое растение как пример. Указанная стадия отмечена как данные пользователя.
- Повторная отправка использует прежний ID. Сообщение об успехе требует серверной версии и снятого признака `dirty`; конфликт или ошибка оставляют черновик.

[Карточки на компьютере](crops/wizard-crops-desktop.png), [предпросмотр](crops/wizard-review-desktop.png), [карточки на узком экране](crops/wizard-crops-mobile.png), [мобильный предпросмотр](crops/wizard-review-mobile.png).

Картографические изображения в автоматическом сценарии заменяются явно подписанной тестовой подложкой. Реальные границы, площадь, форма, API и база в этом сценарии не подменяются. Доступность внешнего ЕГКН не является результатом этой проверки.

## Данные и совместимость

Фактический контур приложения — React + Three.js + Leaflet, Express и SQLite `records` с JSON. Упомянутые в задании MapLibre/TerraDraw/PostGIS не заменяют этот работающий контур. Другие подсистемы проекта могут использовать отдельную PostgreSQL-базу.

Сохранён существующий `Field`: геометрия, площадь и координаты относятся к земле; `crop` — единственная основная культура участка. Добавлено необязательное `cultivation: {seasonId, stage?, plantedOn?}` для текущего периода. Отдельные записи сенсоров, телеметрия и настройки камеры не копируются в участок. Архив сезонов и несколько зон выращивания не реализованы; текущий блок периода можно в дальнейшем вынести в связь по `fieldId`, не меняя геометрию земли.

JSON-записи не требуют SQL-миграции. Старые участки без `cultivation` читаются как раньше. Валидация добавлена к существующему `/api/sync`, а поле разрешено в существующем developer API. Проверяются формат периода, допустимая стадия и реальная календарная дата.

`selectedField` хранит ID участка. Главная получает культуру и стадию из выбранной записи через `fieldScene`, а не из глобальных настроек культуры. Создание и редактирование используют текущие IndexedDB, авторизацию, версии, блокировку синхронизации и серверные подтверждения.

## Проверки

Команды из корня репозитория:

```powershell
pnpm.cmd --filter @egin/mobile build
pnpm.cmd --filter @egin/mobile test
node --test apps/api/tests/cultivation.test.mjs
node apps/mobile/tests/field-journey.cjs
node apps/mobile/tests/crop-assets.cjs
$env:FIELD_EDGE_ONLY='1'; node apps/mobile/tests/field-journey.cjs
Remove-Item Env:FIELD_EDGE_ONLY
```

Браузерные проверки используют локальный Chrome; `CHROME_PATH` позволяет указать другой путь. `field-journey.cjs` использует порт 4949, временную SQLite-базу и тестовую сессию, удаляет только собственные временные данные. `crop-assets.cjs` запускает и закрывает собственный Vite на 4957; `CROP_CAPTURE=1` обновляет снимки моделей.

Подтверждённые результаты:

- TypeScript и production build проходят. Vite предупреждает о существующих крупных chunks Three.js и PDF; сборка успешна.
- 76 модульных проверок мобильного приложения проходят.
- Две проверки API проходят: совместимость/валидация и реальное сохранение четырёх культур, изменение периода, конфликт версий, повторное чтение после перезапуска сервера без обязательного сенсора.
- `field-journey.cjs` проходит с настоящим API/SQLite: рисование и редактирование контура, обязательный выбор культуры, переход назад без потери данных, создание пшеницы и яблони, переключение без пересоздания canvas, перезагрузка, изменение пшеницы на подсолнечник, создание томата, сохранение стадий/даты. Проверены ширина 390 px, ошибка POST, восстановление черновика после reload, повторная отправка без дубликата и чтение серверных записей в чистом браузере. Ошибок JavaScript нет.
- Дополнительный запуск `FIELD_EDGE_ONLY=1` проходит: шаг проверки блокируется до реального серверного подтверждения, гость не получает ложного успеха, его черновик явно восстанавливается после входа, потеря WebGL-контекста позволяет повторно загрузить модель.
- Проверка 3D проходит: четыре культуры × четыре стадии, ракурсы, приближение, мобильный размер, один canvas при переключениях, отсутствие перерисовок в покое, восемь переходов без роста числа GPU-геометрий, освобождение ресурсов, отсутствие ошибок браузера.

### Производительность и пределы проверки

[Сырые итоговые измерения](crops/lifecycle-diagnostics.json). На крупном плане — 29–47 вызовов отрисовки с тенями, 170–439 тысяч треугольников; количество загруженных геометрий стабилизируется после прогрева. В покое сцена останавливает цикл; скрытая вкладка и невидимая сцена приостанавливаются. Смена культуры использует тот же WebGL-контекст и переход 480 мс; reduced motion отключает переходы и инерцию. Ошибка загрузки или потеря контекста показывает доступную повторную загрузку.

Это измерения Chrome/SwiftShader на занятом Windows-хосте. Среднее время CPU-вызова renderer включает прогрев и не равно GPU frame time или FPS. Холодная генерация яблони достигала 1,72 с. Устойчивые 30/60 FPS и расход батареи на физических телефонах не подтверждены. Отдельный профиль на целевых мобильных GPU остаётся необходимым перед заявлением таких характеристик.
