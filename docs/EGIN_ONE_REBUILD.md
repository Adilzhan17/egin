# EGIN One — инженерная переработка

## A. Architecture Audit — аудит до изменений

Проверка кода и запуска выполнена 5 ноября 2026 года. В рабочей копии имеются сторонние незакоммиченные изменения; они сохраняются. Рабочий стек: React/TypeScript, Three.js, Express/Node.js, SQLite; миграция на FastAPI/PostgreSQL не обоснована текущей задачей.

| Функция | Состояние до переработки | Дефект | Изменение |
| --- | --- | --- | --- |
| Поток телеметрии C++ → API → WebSocket | Реализован | Нет публичной демо-сессии | Изолированный демонстрационный доступ |
| Хранение измерений | Реализовано | Состояние симуляции и очередь теряются при рестарте | Версионированное сохранение состояния |
| Физическое устройство | Частично | API и токены есть, нет экрана привязки/выбора, power/radio всегда null | Реестр, безопасная привязка, диагностика и nullable телеметрия |
| Водный/тепловой/солевой баланс | Реализован | Восстановление normal не снимает все неисправности | Воспроизводимые сценарии и восстановление |
| События и тревоги | Отсутствовали | Только последние строки телеметрии | История команд и переходов состояния |
| 3D-сборка | Частично | Пересекающиеся боксы, нет стенок, крепежа и связной разводки | Модульная инженерная геометрия в общей системе координат |
| Срез почвы | Частично | Повторный зонд на фасаде, корни-палочки и одинаковые конусы | Настоящий удаляемый сектор грунта, слои, корни и растительность |
| Выбор детали | Частично | Нет подсветки, фокуса и сброса камеры | Выделение, фокус, подписи, слои и разнесённый вид |
| UI | Частично | Один длинный экран с крупными пустыми секциями | Обзор, двойник, аналитика, диагностика, история |
| Нативный Modbus-декодер | Реализован | Аппаратные драйверы ESP32 отсутствуют | Сохраняется и повторно проверяется |

Аудит не подтверждает физическую сборку, калибровку или полевую связь. Механические размеры корпуса и компоновка электроники — проектная конфигурация; почвенные горизонты, растения и корни — иллюстрация.

## B. Implementation Report — реализация

Публичное название заменено на **EGIN One**, основной маршрут — `/#/egin-one`. Старый `/#/soilcore` и `/api/soilcore` сохранены для совместимости. На главной EGIN обновлена точка входа.

Интерфейс разделён на обзор станции, цифровой двойник, аналитику почвы, диагностику, историю и события. Демонстрация доступна без регистрации. Физические станции привязываются в профиле: название, выбор устройства, выдача токена один раз, отзыв доступа. Переключение режима, прибора или профиля очищает прошлые данные и исключает запоздалые ответы прежнего подключения.

| Область | Основные файлы | Реализованное поведение |
| --- | --- | --- |
| Экран и навигация | `apps/mobile/src/features/soilcore/SoilCorePage.tsx`, `soilcore.css`, `typography.css`; `app/App.tsx`, `features/home/HomePage.tsx` | Пять разделов, переключение источника, адаптивная вёрстка, состояния отсутствующих данных |
| Типы и интерфейс | `types.ts`, `catalog.ts`, `OneIcon.tsx`, `StationPanels.tsx`, `TwinPanel.tsx` | Восемь компонентов с назначением, параметрами, соединениями и обслуживанием; реальные действия управления |
| Сеть и история | `api.ts`, `useStation.ts`, `TelemetryChart.tsx` | HTTP и WebSocket, повторное подключение, догрузка истории, график по времени и выбранному параметру |
| 3D | `SoilCoreScene.tsx`, `scene/DeviceModel.ts`, `scene/SoilEnvironment.ts`, `scene/geometry.ts`, `scene/batch.ts` | Геометрия сборки, вращение/масштаб/панорама, фокус, подсветка, подписи, видимость частей, крышка, разнесённый вид, разрез и полноэкранный режим |
| Сервис EGIN One | `apps/api/src/soilcore/index.mjs` | Реестр, авторизация, ingestion, история, статус свежести, события, WebSocket и SQLite-миграция v2 |
| Модель и протокол | `simulation.mjs`, `native.mjs`, `schemas.mjs` | Балансы воды/тепла/солей/энергии, контрольные точки, процесс настоящего C++ декодера, валидация входящих пакетов |
| Проверки | `apps/api/tests/egin-one.test.mjs`, `apps/mobile/tests/soilcore.cjs` | Сохранность после рестарта, изоляция, аппаратный пакет эмулятора, браузерные действия |

Новые таблицы `soilcore_demo_sessions`, `soilcore_demo_readings`, `soilcore_simulations`, `soilcore_events` добавляются миграцией. Реестр получает название устройства. Старые измерения и токены не удаляются. Модельное состояние, контрольная точка и очередь недоставленных декодированных измерений сохраняются в SQLite. Восстановление точки создаёт новый `run_id`, сохраняет старую историю и не откатывает последовательность `seq`.

Переходы состояния создают события: потеря/восстановление связи, низкий заряд, ошибка зонда, недоступность декодера, сухая почва и высокая EC. Предупреждения о сухости/EC используют демонстрационные пороги 18% и 2000 µS/cm; это не универсальные агрономические нормы.

Подробный контракт: [EGIN One API](../apps/api/src/soilcore/CONTRACT.md).

## C. Engineering Decisions — инженерные решения

### Геометрия и визуализация

Единица сцены — метр. Корпус 120 × 80 × 50 мм, солнечная панель 230 × 195 мм и стойка около 1,12 м — параметры проектной сборки из задания. Корпус имеет стенки, заднюю панель, крышку, уплотнение, винты, кабельные вводы, крепёж к стойке и внутренние опоры. Отдельные группы содержат MCU, питание, батарею, RS485 и радиотракт. Провода соединяют функциональные узлы; в разнесённом виде маршруты меняются вместе с деталями. Это объясняющая инженерная модель, не комплект производственных CAD-чертежей и не результат механического расчёта.

Габариты SEN0604 — 127 × 45 × 15 мм, четыре электрода с выступающей частью 67 мм — сверены с [официальным размерным рисунком DFRobot](https://dfimg.dfrobot.com/wiki/20207/SEN0604_soil-temperature-humidity-ec-and-ph-sensor_dimension_V1.0.jpg). Конструкция модели не повторяет ошибочную трёхэлектродную иллюстрацию. Проектное использование Wio-SX1262 с XIAO ESP32-S3 отделено от наличия физических драйверов; см. [описание комплекта Seeed](https://wiki.seeedstudio.com/wio_sx1262_with_xiao_esp32s3_kit/).

Передняя половина блока грунта действительно скрывается, показывая тот же зонд в трёх слоях почвы. Ветвящиеся корни, неровности, камни и растения процедурные; цвет грунта отражает влажность модели. Слои, корни и кольцо контакта подписаны как иллюстрация: одно точечное измерение не представлено картой влажности поля.

Three.js использует PBR-материалы, окружение, мягкие тени, объединение статичных мешей и инстансинг растений. Рендер запускается при изменениях, управлении камерой и анимации; вне экрана и в скрытой вкладке останавливается. DPR ограничен, кадры ограничены сверху 30 Гц. Это ограничение нагрузки, а не обещание 30 FPS на любом устройстве. `preserveDrawingBuffer` сохраняет изображение между редкими кадрами и позволяет проверять реальные пиксели WebGL. Геометрии, материалы, текстуры, наблюдатели и обработчики освобождаются при размонтировании. Для недоступного WebGL остаются технические панели и телеметрия.

### Симуляция и телеметрия

Единое модельное время находится на сервере. Дождь меняет инфильтрацию и запас воды, засуха — испарение, засоление — массу растворённых солей; EC зависит также от воды. Температура стремится к модельным условиям с задержкой. Мощность панели и нагрузка изменяют запас энергии. При низком заряде действует уменьшенная модельная нагрузка. Ускорение 1/60/360, пауза, сброс и восстановление применяются к одной модели.

Поток демонстрации: модель → Modbus RTU-кадр → настоящий переносимый C++ декодер → проверенные значения → SQLite → HTTP/WebSocket → графики/3D. При отсутствии бинарника новые измерения не подменяются значениями из JavaScript. Нативный процесс выделен в `native.mjs`; схемы физических пакетов — в `schemas.mjs`.

Протокол SEN0604 сверяется с [документацией DFRobot](https://wiki.dfrobot.com/sen0604/docs/20297): функция 03, четыре регистра, big-endian, влажность/температура/pH с делителем 10, знаковая температура, EC в µS/cm, CRC16 low byte first. Декодер проверяет длину, адрес, функцию, CRC, исключения, диапазоны и тайм-аут. Нативное ядро и его ограничения описаны в [firmware README](../firmware/soilcore/README.md).

Физические данные принимаются только с токеном зарегистрированной станции. Владелец и источник определяются сервером. Отсутствующие power/radio остаются `null`; в UI показано «Нет данных». По умолчанию влажность не откалибрована для конкретной почвы, pH требует сравнения с лабораторией. EC не переводится в NPK или гумус.

SQLite сохранён как работающая база репозитория. Смена на PostgreSQL/FastAPI не требовалась для этих сценариев и разрушила бы существующие интеграции. Авторитетная очередь симулятора хранится на сервере: запись доставленной истории и очистка очереди выполняются в транзакции. Сервер переживает рестарт; это не гарантия доставки по физическому радиоканалу.

Проверки выполнялись локально на Windows 5 ноября 2026 года. Ниже команды из корня репозитория, если явно не указана другая папка.

Браузерный сценарий использует Chrome/Playwright и программный WebGL. ## E. Remaining Limitations — границы готовности

- Работают локальная инженерная демонстрация, серверная модель, native C++ Modbus-декодер, реестр, приём валидированной телеметрии, хранение, поток, история, события и диагностика.
- **Физическое оборудование не подключено.** Не реализованы и не проверены платформенные UART/RS485, Wi-Fi/TLS, ESP-IDF, управление реальным питанием, flash-журнал, RTC/OTA и полевой LoRaWAN. Для готовой прошивки ESP32 нужны платформенные адаптеры и испытания. Нативный CLI сам не отправляет HTTPS; симуляционный сервер читает его вывод.
- Нужны электрическая схема, проверка питания SEN0604 (5–30 В), настройки зарядника LiFePO₄, температура заряда, GPIO, токи, время прогрева и реальная автономность. IP66 — целевое требование без испытаний. Геометрия батареи/плат объясняет компоновку и не подтверждает закупочную спецификацию.
- Модель воды/солей/температуры/энергии детерминирована, но не откалибрована полевыми данными. pH и влажность нуждаются в проверке для конкретной почвы; прогноз урожая и подтверждённый индекс плодородия не заявляются.
- Текущая координация симуляций и WebSocket рассчитана на один процесс API. Несколько workers требуют блокировок и pub/sub. Гостевые данные живут 24 часа. История ограничена 5000 измерениями на режим/владельца, события — 1000, очередь — 1000; после удаления старых записей дедупликация давних `seq` не гарантируется.
- Проверены desktop Chrome и мобильный размер в Chrome. Реальные Android/iOS GPU, долговременные утечки, нагрузка и стабильный FPS не измерены; Docker и production-развёртывание в рамках этой переработки не выполнялись.

## F. Run Instructions — локальный запуск

Требуются Node.js с `node:sqlite` (в проверенном окружении Node 24), pnpm, C++17/CMake. Python нужен для теста восстановления CLI. Команды PowerShell из корня репозитория:

```powershell
pnpm.cmd install --frozen-lockfile
cmake -S firmware/soilcore -B firmware/soilcore/build
cmake --build firmware/soilcore/build --config Debug
ctest --test-dir firmware/soilcore/build -C Debug --output-on-failure
pnpm.cmd --filter @egin/mobile build
```

Для встроенного preview-сервера, обслуживающего frontend и API на одном origin:

```powershell
# Сохранённая локальная база этого рабочего окружения; не удалять при перезапуске.
$env:DATA_DIR = Join-Path $env:TEMP 'egin-local-data'
Set-Location apps/api
node tests/preview.mjs
```

Открыть **http://localhost:4935/#/egin-one**. Гостевая симуляция запускается без прибора и входа. Раздел «Реальный прибор» требует профиль EGIN; отсутствие измерений показывается явно. Preview также занимает порт 4938 для существующего developer portal.

По умолчанию API ищет `soilcore_cli` в `firmware/soilcore/build` и `build/Debug`. Для другой сборки до запуска задайте абсолютный путь:

```powershell
$env:SOILCORE_CLI = 'C:\path\to\soilcore_cli.exe'
```

Для другой локальной установки задайте `DATA_DIR` в постоянной папке пользователя вместо временного каталога. Не запускайте второй API-процесс с той же SQLite-базой для симуляций. Внешний доступ требует HTTPS и корректных Origin/RP-настроек; preview предназначен для локальной проверки.

Браузерный тест запускает отдельный сервер на 4945 и свою временную базу. По умолчанию Chrome берётся из `C:\Program Files\Google\Chrome\Application\chrome.exe`; путь можно изменить через `CHROME_PATH`. `SOILCORE_CLI` также учитывается тестом. Тест не меняет локальные пользовательские станции.
