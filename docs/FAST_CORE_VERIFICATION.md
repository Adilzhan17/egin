# EGIN Fast Core — проверено локально

Проверен существующий проект в production-сборке Compose на `http://localhost:3000`, 4 октября 2026 года. FastAPI, PostgreSQL/PostGIS и исходный MapLibre сохранены. JS используется для представления, предварительной геометрии, состояния, кеша и оптимистичных действий; секреты, права, окончательные расчёты, ML и LLM остаются в CORE.

Полной production-готовностью это не называется: публикация ожидает сверки изменившегося SSH-ключа, Google доступ отложен пользователем, а точность агрономических объяснений локальной модели ограничена.

| CLIENT ENGINES — Chat | **PASS**: версии, optimistic UUID/retry, история и черновики; сервер подтверждает права и изменения |
| CLIENT ENGINES — Sensor | **Отключён**: оборудования нет; фиктивной телеметрии в UI нет |

| Containers | **web + core + db**, сборка и `docker compose up -d --wait` прошли; volume БД сохранён |

Проверки исходников: TypeScript и ESLint — PASS; 62 backend-теста за 29,22 с, включая финальную нормализацию AI-контекста и обязательное получение разрешённого списка полей; 5 регрессий query-cache, 6 app-store/recovery/onboarding, настоящий Chromium IndexedDB. Полный Playwright: **9/9 PASS за 98,3 с**, без skipped/flaky. Основные браузерные сценарии используют реальный CORE, БД, SSE и LLM. Для воспроизведения гонки onboarding задерживается настоящий bootstrap-ответ, а для защиты от дубликатов отдельно инжектируется повтор настоящего события. Это не выдаётся за полностью пассивный тест.

Версии образов, кейсы и результаты: [fast-core-verification.json](../artifacts/fast-core-verification.json). Чат: [измерения](../artifacts/chat-browser-verification.json), [390 px](../artifacts/chat-mobile-390.png), [короткий viewport](../artifacts/chat-mobile-short-viewport.png).

После полного девятисценарного прогона изменялась только нормализация/выбор инструментов AI на сервере. На окончательном CORE повторно пройден реальный AI browser E2E: **PASS, 22,8 с** — tool/token/completed, одно SSE между страницами и история после reload. Web/GIS/chat/offline/bootstrap после общего прогона не менялись; привязки результатов к образам сохранены в JSON.

Шесть точных вопросов из ТЗ: [результаты и фактические ошибки](../artifacts/assistant-requested-questions-review.json). После исправления обязательного получения списка полей выполнен [отдельный повтор](../artifacts/assistant-requested-fields-recheck-review.json): инструмент вернул все шесть разрешённых записей, текст модели перечислил только три уникальных названия; первый токен — 32,49 с, полный ответ — 33,63 с. Исходный шестисценарный результат не переписан этим повтором. Ни один из этих прогонов не объявляется «6/6 качественных ответов».

Сравнение размера snapshot: прежний `/dashboard` — 98 247 байт; компактный `/bootstrap` — 20 893 байта JSON, 5 239 байт gzip. Это разные формы ответа: bootstrap сохраняет сводку, а подробности запрашиваются при открытии поля.

Производительность: [before](../artifacts/performance-before.md), [after](../artifacts/performance-after.md), [warm cache](../artifacts/performance-after-warm-home.md). Baseline — один прогон на сценарий; после ENOSPC подробный исходный trace потерян, исходные 15 строк таблицы сохранены независимо и восстановлены с округлённой точностью. Это не повтор baseline на изменённом приложении. Доступность погоды изменилась между измерениями: исходный provider иногда возвращал unavailable; итоговый snapshot содержит реальный прогноз. Методика и ограничения сравнения перечислены в отчётах.

| Главная, 390×844 | FCP до → после | LCP до → после |
|---|---:|---:|
| Без ограничения сети | 512 → 84 мс | 2 188 → 480 мс |
| Fast 4G / CPU ×4 | 2 012 → 688 мс | 8 036 → 2 624 мс |
| Slow 4G / CPU ×4 | 6 432 → 1 940 мс | 17 612 → 5 984 мс |

В контролируемом cold-прогоне Service Worker отключён, как и в исходном проекте, чтобы CDP учитывал lazy chunks и применял к ним ограничения сети. JavaScript главной: 2 425,2 → 182,7 KiB (−92,5%); API: 6 → 2 запроса. Карта: 2 425,2 → 671,5 KiB JS; первый WebGL draw на Slow 4G: 46 241 → 16 367 мс. Загруженность сервера в production этими числами не измерялась.

С заполненным настоящим SW/IndexedDB-кешем LCP главной — 252 мс без CPU slowdown и 772–788 мс при CPU ×4. Страницы не загружают JS повторно; ограничение сети через page CDP не гарантирует такой же режим для запросов из SW, поэтому warm-числа не выдаются за полноценный 4G-тест. Измеренный navigation TTFB 9–13 мс также не доказывает configured RTT 150/400 мс.

Компромисс зафиксирован: без ограничения сети LCP четырёх остальных страниц вырос до 640–780 мс; несколько long-task сумм выросли. На двух ограниченных сетях LCP улучшился на всех пяти маршрутах. Синтетическое menu Event Timing доходило до 104 мс — цель «все взаимодействия быстрее 100 мс» не объявляется достигнутой. Полная таблица улучшений и регрессий: [performance-comparison.md](../artifacts/performance-comparison.md).

Запуск: `docker compose up --build`. Для локальной проверки: `http://localhost:3000`, демо-аккаунт из README. Google остаётся последним этапом по просьбе пользователя; конкретные настройки — [GOOGLE_ACCESS.md](GOOGLE_ACCESS.md). Публичная ссылка не объявляется работающей до успешного деплоя и проверки.
