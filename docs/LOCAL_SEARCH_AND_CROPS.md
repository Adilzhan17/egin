# Поиск мест, локальная модель и обновление культур

**Обновление 06.11.2026:** по просьбе пользователя все четыре 3D-культуры и renderer восстановлены без изменений из `origin/main` (`b23e4a9`). Карточки теперь содержат снимки этих исходных моделей. Описание переработанной геометрии и её проверки ниже относится к предыдущей, отменённой версии; функции поиска сохранены.

Локальная версия: http://localhost:4935. Изменения не опубликованы на внешнем сервере.

## Как проверить

1. Откройте **Мои участки → Добавить участок**. В поле «Адрес, город или район» введите `Кызлорда`, `Астна`, `Алм` или `тр`. Выберите подсказку мышью или стрелками и Enter. Карта приблизит выбранное место. Поиск есть также в окне выбора контура ЕГКН.
2. Для улицы или дома введите город и адрес, например `Алматы Абая 10`, и нажмите **Найти адрес**. Проверьте город, район и номер дома в результате. Если дом не найден, можно выбрать город и найти участок на карте. Адрес не создаёт кадастровую границу и не подтверждает право собственности.
3. На странице **Рынок** введите `тр`: появляются «Трактор», «Трейлер», «Триммер», «Трактор в аренду». `тррарктр` предлагает «Трактор». Подсказки работают независимо от доступности базы объявлений; настоящие объявления по-прежнему требуют настроенного PostgreSQL. На этом локальном запуске база Рынка не подключена, поэтому список объявлений показывает состояние недоступности. Существующие подсказки из опубликованных объявлений сохраняются, когда база доступна.
4. В мастере участка задайте границу и выберите культуру. В карточках яблони и пшеницы использованы оригинальные JPG из пользовательских ZIP. В 3D переработаны крона, плоды, колосья, чешуи, ости и фактуры. Модель объёмная, её можно вращать и приближать.

ZIP содержали JPG и PSD, а не mesh/GLB/FBX. 3D создана по визуальным референсам; это не импорт готовой геометрии. Подробности, контрольные суммы и подготовка оригинальных изображений: [источники культур](crop-assets/SOURCES.md). Шахматный фон присутствует в исходных JPG.

## Что работает локально

- Справочник из **13 847** населённых пунктов и административных единиц Казахстана, с координатами и альтернативными названиями. Содержимое взято из [GeoNames KZ](https://download.geonames.org/export/dump/KZ.zip), лицензия [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). Источник и дата загрузки записаны в `apps/api/src/search/places-kz.json`. Изменения: отобраны населённые пункты и административные единицы, приведены русские отображаемые названия, добавлены поля для поиска. Справочник не содержит полного списка улиц и домов.
- Префиксный поиск, исправление опечаток с перестановками букв и поддержка неверной раскладки. Основные термины сельского хозяйства хранятся отдельно от объявлений.
- Настоящая локальная нейросеть [multilingual MiniLM L12](https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2/tree/e8f8c211226b894fcb81acc59f3b34ba3efd5f42), закреплённая ревизия, Apache 2.0. Квантованная ONNX-модель 118 453 870 байт и tokenizer 9 081 518 байт. CPU, 2 потока, 384-мерные эмбеддинги. Модель уточняет порядок найденных вариантов, а не генерирует координаты или объявления. Запросы для неё не отправляются облачной нейросети.
- При остановке модели сохраняются префиксы и исправление опечаток. API возвращает фактический режим: `local-prefix`, `local-hybrid` или `local-fuzzy`.

Точный адрес ищется по явной кнопке через [Photon / OpenStreetMap](https://github.com/komoot/photon/blob/master/docs/api-v1.md); запрос адреса при этом отправляется этому сервису. Это требует интернета. Выбранный город ограничивает область и город результатов. У публичного сервиса нет гарантии полноты адресов или доступности. Есть ограничение частоты, кеш и возврат к локальному городу при сбое. `PLACE_SEARCH_URL` позволяет подключить свой Photon. Подложки карт тоже требуют сети. «Локально» здесь означает на компьютере, где запущен API EGIN; модель не встроена в телефон.

## Повторный запуск

Из корня репозитория в PowerShell:

```powershell
powershell.exe -ExecutionPolicy Bypass -File scripts/start-local-search.ps1
$env:DATA_DIR = Join-Path $env:TEMP 'egin-local-data'
Set-Location apps/api
node tests/preview.mjs
```

Приложение — `http://localhost:4935`, модель — `http://127.0.0.1:4939/health`. Оба сервиса слушают только этот компьютер. Скрипт проверяет уже запущенную модель. На новом компьютере сначала добавьте `-Setup`: это создаст Python venv, установит зависимости и скачает закреплённые веса. Нужен Python 3.13. Данные модели находятся в `%LOCALAPPDATA%/EGIN/models/multilingual-minilm`, окружение — `%LOCALAPPDATA%/EGIN/search-runtime`, журналы — `%TEMP%/egin-local-search-*.log`. Веса не добавлены в Git и не попадают в браузер.

API по умолчанию обращается к модели на `127.0.0.1:4939`. Для другого адреса установите `LOCAL_SEARCH_INFERENCE_URL`. `MARKET_INFERENCE_URL` отдельно включает семантический поиск опубликованных объявлений при настроенном PostgreSQL/pgvector.

Пересборка интерфейса: `pnpm.cmd --filter @egin/mobile build`. Обновление справочника: `python apps/api/scripts/prepare-place-index.py`. Открытая вкладка со старой версией обновляется через Ctrl+F5.

## Проверка

Сборка прошла. Пройдено 8 проверок API с настоящей ONNX-моделью, 2 проверки исходных изображений, браузерная проверка поиска и полный сценарий участка: четыре культуры, стадии, сохранение, восстановление черновика, сетевой сбой, повтор без дубликатов и загрузка с сервера в новом браузере. Результаты и живой адресный запрос записаны в [verification.json](search/verification.json).

```powershell
$env:MARKET_TEST_INFERENCE_URL = 'http://127.0.0.1:4939'
node --test apps/api/tests/local-search.test.mjs apps/api/tests/market-search.test.mjs
node apps/mobile/tests/local-search.cjs
node apps/mobile/tests/crop-reference-assets.cjs
node apps/mobile/tests/field-journey.cjs
```

Backend: префиксы, пользовательская опечатка, раскладка, RU/KK названия, настоящие координаты, привязка адреса к городу, отсутствие сетевого запроса при локальной подсказке, кеш, сбой геокодера, валидация API, реальные эмбеддинги и отказ модели.

Браузер: выбор города клавиатурой, перемещение карты без создания контура, защита от запоздавшего ответа, ширина 390 px, отказ поиска адреса, исходные JPG, опечатка и клавиатура на Рынке. Карта в автоматическом тесте использует явно обозначенную тестовую подложку; реальные адресные запросы проверяются отдельно.
